# http_shell 使用与启动文档

> 本文档基于项目真实源码编写，聚焦于 `mcp.go` 的 MCP (Model Context Protocol) SSE 服务端实现。
> 项目 module 名：`http_shell`；MCP 服务端口：`8080`；暴露工具：`execute_shell`。

---

## 1. 项目简介

`http_shell` 是一个用 Go 编写的 HTTP Shell 工具，核心能力是把"执行 shell 命令"通过 HTTP 暴露出去。

- **普通 HTTP Shell 模式**：通过 `POST /` 提交 `cmd`、`cmd-base64`、`cmd-base64-url`、`cmd-file` 等表单字段，服务端用 `sh -c` 执行命令并**逐行流式返回**输出。
- **MCP SSE 模式**：通过启动参数 `mcp` 激活，在原有 HTTP Shell 能力之上，额外在 `/mcp` 端点提供符合 **MCP (Model Context Protocol) 标准**的 SSE 服务端，向各类 MCP 客户端（如 Claude Desktop、Cursor、通用 MCP 客户端）暴露一个名为 **`execute_shell`** 的工具，用于远程执行任意 shell 命令。

`mcp.go` 实现了 MCP SSE 协议的核心，包括：

- MCP 协议消息结构体（`MCPMessage`、`MCPError`、`MCPTool` 等）；
- SSE 长连接的管理（`SSEConnection`）；
- MCP 请求的分发处理（`MCPHandler`、`mcpSSEHandler`、`mcpRequestHandler`）；
- `execute_shell` 工具的注册与执行。

## 2. 架构说明

### 2.1 入口与两种启动模式（`src/main.go`）

`main()` 根据第一个命令行参数决定启动模式：

```go
func main() {
    if len(os.Args) > 1 && os.Args[1] == "mcp" {
        log.Println("启动 MCP SSE 模式")
        startMCPServer()
        return
    }
    startHTTPShell()
}
```

| 启动命令 | 模式 | 注册的路由 | 说明 |
| --- | --- | --- | --- |
| `http-shell`（无参数） | 普通 HTTP Shell | `GET/POST /` | 仅暴露 Shell 命令执行服务 |
| `http-shell mcp` | MCP SSE | `GET/POST /mcp` + `GET/POST /` | 在保留原 HTTP Shell 的同时，额外提供 MCP SSE 端点 |

两个启动函数都监听 **`:8080`**：

```go
func startHTTPShell() {
    http.HandleFunc("/", handler)
    log.Fatal(http.ListenAndServe(":8080", nil))
}

func startMCPServer() {
    http.HandleFunc("/mcp", mcpSSEHandler)
    http.HandleFunc("/", handler)
    log.Fatal(http.ListenAndServe(":8080", nil))
}
```

### 2.2 `src/mcp.go` 核心结构与职责

| 结构体 / 函数 | 职责 |
| --- | --- |
| `MCPMessage` | 标准 MCP JSON-RPC 消息：`jsonrpc`、`id`、`method`、`params`、`result`、`error` |
| `MCPError` | MCP 协议错误：`code`、`message`、`data` |
| `MCPTool` | 工具定义：`name`、`description`、`inputSchema` |
| `MCPToolCallResult` | 工具执行结果：`content`（`[]MCPContent`）、`isError` |
| `MCPContent` | 工具返回内容：`type`（此处固定 `text`）、`text` |
| `SSEConnection` | 管理一条 SSE 长连接：持有 `http.ResponseWriter` 与 `http.Flusher`；`WriteEvent(eventType, data)` 写入并 flush 一条事件；`Close()` 标记连接关闭；内部用互斥锁 `mu` 保证并发安全 |
| `sseConnections` / `sseConnectionsLock` | 全局 SSE 连接管理器，按 `clientID` 记录所有活跃连接 |
| `MCPHandler` | MCP 逻辑处理器：维护 `tools` 工具映射（`map[string]func(map[string]interface{}) MCPToolCallResult`） |
| `NewMCPHandler()` | 构造 `MCPHandler` 并调用 `registerTools()` 注册工具 |
| `registerTools()` | 注册 `execute_shell` 工具，绑定到 `executeShellCommand` |
| `executeShellCommand(params)` | 读取 `params["command"]`，用 `sh -c` 执行，返回 stdout+stderr 拼接结果；`command` 缺失时返回中文错误 |
| `HandleToolsList()` | 返回工具列表（当前仅 `execute_shell`，含 inputSchema） |
| `HandleToolCall(params)` | 按 `params["name"]` 分发到对应工具函数，解析 `arguments` 后调用 |
| `mcpSSEHandler(w, r)` | `/mcp` 端点总入口：POST 走 `mcpRequestHandler`；GET 建立 SSE 长连接 |
| `mcpRequestHandler(w, r)` | 处理 POST 过来的 JSON-RPC 请求，返回 JSON 响应 |

### 2.3 命令执行（`src/mcp.go` 中的 `executeShellCommand` 与 `src/exec.go`）

- **MCP 模式**：`executeShellCommand` 使用 `exec.Command("sh", "-c", cmd)` 执行，捕获 stdout 与 stderr，返回合并文本；通过退出码非 0 判断 `isError`。
- **普通模式**：`src/exec.go` 的 `handler` 解析 `cmd` / `cmd-base64` / `cmd-base64-url` / `cmd-file` 表单参数，`executeCommand` 用 `sh -c` 执行并**逐行流式 flush** 输出。

两种模式都依赖 `sh`，因此运行环境需具备 POSIX 风格的 `sh`（Docker 内的 Alpine/Ubuntu 等均可）。

## 3. 启动方法

### 3.1 直接编译运行（本地有 Go 环境）

项目 `go.mod` 声明 `go 1.23.12`。

```bash
# 进入源码目录
cd src

# 编译（生成二进制 http-shell）
CGO_ENABLED=0 go build -o http-shell .

# 方式一：普通 HTTP Shell 模式（无参数）
./http-shell
# 日志：开启http端口 :8080

# 方式二：MCP SSE 模式（带 mcp 参数）
./http-shell mcp
# 日志：
#   启动 MCP SSE 模式
#   MCP SSE 服务启动在端口 :8080
```

也可以直接用 `go run` 启动 MCP 模式：

```bash
cd src
go run . mcp
```

> 注意：MCP 模式同时保留了普通 HTTP Shell 服务（`/` 路径仍可用）。

### 3.2 Docker 启动

项目提供 4 个 Dockerfile，区别在于**运行阶段的基础镜像**（决定容器内是否带 docker CLI / podman）：

| Dockerfile | 基础镜像 | 容器内工具 | 适用场景 |
| --- | --- | --- | --- |
| `Dockerfile` | 默认 `scratch`（可用 `LATEST_FROM_BASE` 构建参数覆盖） | 极简，无 docker CLI | 纯 shell 命令执行 |
| `Dockerfile.docker` | `adockero/http-shell:alpine` + `apk add docker-cli` | 带 **docker-cli** | 需要在容器内执行 `docker` 命令 |
| `Dockerfile.docker.ubuntu` | `ubuntu:22.04` + `apt install docker.io`，从 `adockero/http-shell:alpine` 拷贝二进制 | 带 **docker.io** | 需要在容器内执行 docker（Ubuntu 系） |
| `Dockerfile.podman` | `mgoltzsche/podman`，从 `adockero/http-shell` 拷贝二进制 | 带 **podman** | 需要在容器内执行 `podman` 命令 |

各 Dockerfile 都通过 `EXPOSE 8080/TCP` 暴露 8080 端口，并以 `ENTRYPOINT ["/http-shell"]` 启动二进制。

#### 构建示例

```bash
cd golang/http_shell

# 基础版（scratch）
docker build -t http-shell:latest .

# 带 docker-cli 版
docker build -f Dockerfile.docker -t http-shell:docker .

# 带 docker.io（Ubuntu）版
docker build -f Dockerfile.docker.ubuntu -t http-shell:docker-ubuntu .

# 带 podman 版
docker build -f Dockerfile.podman -t http-shell:podman .
```

#### 运行并覆盖 ENTRYPOINT 以开启 MCP 模式

默认 `ENTRYPOINT ["/http-shell"]` 走普通模式。Docker **不支持直接覆盖 ENTRYPOINT 参数**，若镜像的 ENTRYPOINT 是固定数组，需在 `docker run` 中用 `--entrypoint` 显式指定命令，把 `mcp` 作为参数传入：

```bash
# 普通模式
docker run --rm -p 8080:8080 http-shell:latest

# MCP 模式：覆盖 ENTRYPOINT，把 mcp 参数传给二进制
docker run --rm -p 8080:8080 --entrypoint /http-shell http-shell:latest mcp
```

带 docker-cli 的镜像要能操作宿主机 Docker，通常还需要挂载 docker socket（示例）：

```bash
docker run --rm -p 8080:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --entrypoint /http-shell \
  http-shell:docker mcp
```

> 提示：如果希望"改镜像里的 ENTRYPOINT 为 `["/http-shell", "mcp"]`"，请自行基于这些 Dockerfile 派生新镜像，本文档不修改源码。

### 3.3 端口说明

- 所有模式统一监听 **8080** 端口（`http.ListenAndServe(":8080", nil)`）。
- 容器运行需通过 `-p 8080:8080` 将端口映射到宿主机。
- Windows 下若用 `run_mcp_test.bat` / `run_test.bat` 在本地直接 `go run . mcp` 启动，同样监听本机 8080。

## 4. MCP 协议端点说明

MCP 模式新增的端点为 `GET/POST /mcp`（`src/main.go` 中 `http.HandleFunc("/mcp", mcpSSEHandler)`）。

### 4.1 GET /mcp —— 建立 SSE 长连接

`mcpSSEHandler` 对 GET 请求的处理流程：

1. 校验 `http.Flusher` 是否可用，否则返回 `500 SSE not supported`；
2. 设置 SSE 响应头：
   - `Content-Type: text/event-stream`
   - `Cache-Control: no-cache`
   - `Connection: keep-alive`
   - `Access-Control-Allow-Origin: *`
3. 构造 `SSEConnection` 并注册到全局 `sseConnections`；
4. **立即推送一条 `endpoint` 事件**，通知客户端后续 POST 命令的端点：

   ```
   event: endpoint
   data: {"jsonrpc":"2.0","method":"notifications/endpoint","params":{"endpoint":"/mcp"}}
   ```

5. 之后阻塞等待客户端断开（`<-r.Context().Done()`），断开时清理连接并记日志。

### 4.2 POST /mcp —— 发送 JSON-RPC 请求

`mcpRequestHandler` 接收 POST 请求体，**支持两种格式**：

- **直接 JSON**：请求体即为 JSON-RPC 对象；
- **SSE 格式**：请求体以 `"data: "` 开头，服务端会去掉 `data: ` 前缀后再解析 JSON。

```go
if strings.HasPrefix(string(body), "data: ") {
    jsonStr = strings.TrimPrefix(string(body), "data: ")
} else {
    jsonStr = string(body)
}
json.Unmarshal([]byte(jsonStr), &msg)
```

服务端会对请求方法 `msg.Method` 进行分发，支持的方法及对应响应：

| Method | 行为 | 响应 result |
| --- | --- | --- |
| `notifications/*`（无 id） | 忽略通知，直接返回 `{}` | — |
| `initialized`（无 id） | 握手完成通知，返回 `{}` | — |
| `initialize` | 握手请求 | `protocolVersion: "2025-06-18"`、`serverInfo: {name: "http-shell-mcp", version: "1.0.0"}`、capabilities（tools/prompts/resources/logging） |
| `tools/list` | 列出工具 | `{tools: [execute_shell 定义]}` |
| `tools/call` | 调用工具 | 工具执行结果 `{content, isError}` |
| `prompts/list` | 列出提示词 | `{prompts: []}`（空） |
| `resources/list` | 列出资源 | `{resources: []}`（空） |
| `ping` | 健康检查 | `{}` |
| 其他 | 未知方法 | `error: {code: -32601, message: "Method not found"}` |

所有响应都以 `Content-Type: application/json` 返回。

### 4.3 `execute_shell` 工具

- **名称**：`execute_shell`
- **描述**：`Execute a shell command and return the output`
- **输入参数 inputSchema**：

  ```json
  {
    "type": "object",
    "properties": {
      "command": {
        "type": "string",
        "description": "The shell command to execute"
      }
    },
    "required": ["command"]
  }
  ```

- **返回**：`MCPToolCallResult`，形如：

  ```json
  {
    "content": [
      { "type": "text", "text": "<stdout+stderr 合并输出>" }
    ],
    "isError": false
  }
  ```

  - `command` 缺失或非字符串时，返回 `isError: true`，`text` 为 `错误: 缺少 'command' 参数`；
  - 命令通过 `sh -c` 执行；
  - `isError` 由退出码是否为 0 决定（退出码非 0 时为 `true`）；
  - 输出为 stdout 与 stderr 的拼接结果。

## 5. 使用示例

### 5.1 curl 直接调用（POST JSON-RPC）

假设服务已在 `localhost:8080` 以 MCP 模式运行。

**1) initialize 握手**

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

**2) initialized 通知**（握手后通知服务端初始化完成）

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'
```

`initialized` 无 id 时被当作通知处理，返回 `{}`。

**3) tools/list 列出工具**

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

**4) tools/call 调用 execute_shell 执行 `date`**

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"execute_shell","arguments":{"command":"date"}}}'
```

**5) tools/call 调用 execute_shell 执行 `echo`**

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"execute_shell","arguments":{"command":"echo hello from http_shell"}}}'
```

**6) ping 健康检查**

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":4,"method":"ping"}'
```

### 5.2 使用 SSE 格式的请求体（`data: ` 前缀）

POST 请求体也支持 SSE 格式（服务端会自动去掉 `data: ` 前缀）：

```bash
curl -X POST http://localhost:8080/mcp \
  -H "Content-Type: text/event-stream" \
  --data 'data: {"jsonrpc":"2.0","id":1,"method":"tools/list"}
'
```

### 5.3 GET 建立 SSE 连接（观察服务器推送的 endpoint 事件）

```bash
curl -N http://localhost:8080/mcp
```

连接建立后服务端会推送一条 `endpoint` 事件，随后保持连接直到客户端断开。

> 说明：本实现中，POST 请求的响应通过 HTTP 响应体（`application/json`）直接返回，而上文测试代码（`tests/mcp_sse_test.go`）采用"先开 GET SSE 流、再 POST 命令、从 SSE 流实时读取 `message` 事件"的完整 MCP 客户端流程。两种方式均可与该服务交互。

### 5.4 用 MCP 客户端连接

得益于 `/mcp` 同时支持 SSE 长连接与 POST JSON-RPC，标准 MCP（Streamable HTTP / SSE）客户端可以把服务当作"HTTP 上的 MCP 服务端"接入。

**方式一：URL 方式（HTTP 服务地址）**

在支持远程 MCP Server 的客户端（如 Cursor、Claude Desktop 的远程/自定义 MCP 配置、mcp 通用客户端）中配置：

```
URL: http://localhost:8080/mcp
```

**方式二：command 方式（本地启动二进制）**

在支持本地命令启动 MCP Server 的客户端中配置：

```
command: http-shell
args: ["mcp"]
```

（需确保 `http-shell` 可执行文件在 PATH 中，且客户端具备执行该命令的环境；若用 Docker，可改为 `docker` + `run` 参数，见第 3.2 节。）

> 不同客户端对 MCP 传输的配置字段略有差异（`url` / `command`+`args` / `npx` 等），请以你所用客户端的最新配置格式为准，核心地址均为 `http://localhost:8080/mcp`，工具名为 `execute_shell`。

### 6.3 测试思路

以 `mcp_sse_test.go` 中的 `TestMCPExecuteDateCommand` 为例，测试流程为：

1. **建立 SSE 连接**：`http.GET /mcp`，校验响应头 `Content-Type: text/event-stream`；
2. **读取初始 endpoint 事件**：用 `bufio.Scanner` 逐行读取 SSE 流，等待第一条 `endpoint` 事件；
3. **发送 `tools/list`**：POST JSON-RPC 请求，从 SSE 流接收 `message` 事件并解析工具列表；
4. **发送 `tools/call` 执行 `date`**：构造 `{name:"execute_shell", arguments:{command:"date"}}`，校验返回的 `content[0].text` 是否包含日期/时间特征（如英文月份缩写、`:`、`-`、`/` 等），并校验 `isError` 为 false。

其余集成测试（`mcp_integration_test.go`、`mcp_full_test.go`）用 `httptest.NewServer` 自建测试服务，不依赖真实端口，覆盖传输与协议解析逻辑。

## 7. 注意事项 / 安全提示

> ⚠️ **高危：请务必阅读**

- **可执行任意 shell 命令**：`execute_shell` 工具会把 `command` 原样交给 `sh -c` 执行，等价于在服务所在机器上开放了一个**任意命令执行后门**。任何能调用该工具的人都能执行 `rm -rf /`、读取敏感文件、篡改系统等任意操作。
- **无鉴权**：当前实现**没有任何鉴权、认证或白名单机制**，`GET/POST /mcp` 与 `GET/POST /` 均对任意访问者开放。
- **勿暴露在公网**：请勿将服务绑定到公网地址或通过公网端口转发。仅在可信的内网环境、本地开发或受控的容器网络中使用。
- **尽量使用容器隔离**：若需对外使用，建议运行在隔离容器中（见第 3.2 节），并限制为只读挂载、最小化权限，避免直接获得宿主机完整权限。
- **端口与网络**：服务固定监听 8080。容器场景请按需映射端口，并考虑用防火墙/反向代理限制来源 IP。
- **日志会记录命令**：服务端会打印收到的请求体（含命令内容），请勿在日志中泄露敏感信息。
- **依赖 `sh`**：执行依赖容器/系统内的 `sh`，非 POSIX 环境（如纯 Windows 无 WSL）可能无法执行。
- **`Access-Control-Allow-Origin: *`**：SSE 响应设置了跨域全放行，进一步降低了对浏览器侧调用方的限制，请谨慎对待。
